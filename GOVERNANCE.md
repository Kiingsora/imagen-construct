# Governance

## Current model

Imagen Construct begins with a benevolent-maintainer model. The primary maintainer owns release decisions, repository administration, and final scope arbitration while the contributor base is small.

## Decision process

- Product scope follows [PROJECT_BRIEF.md](PROJECT_BRIEF.md) and [docs/MVP.md](docs/MVP.md).
- Significant technical decisions are recorded as ADRs.
- New features begin with an issue that states user value and acceptance criteria.
- Model integrations require licensing and hardware documentation.
- Roadmap changes are based on demonstrated user or implementation evidence.

## Maintainer responsibilities

- review contributions in a reasonable and consistent manner;
- communicate uncertainty and project capacity honestly;
- protect the layer-first, local-first, model-agnostic principles;
- keep contributor tasks small and understandable;
- avoid presenting research ideas as implemented features;
- document breaking decisions.

## Future evolution

When sustained contributors emerge, maintainership can be granted based on repeated high-quality contributions, review activity, reliability, and alignment with project standards. A more distributed governance model should be adopted before the project depends on multiple maintainers for releases.
